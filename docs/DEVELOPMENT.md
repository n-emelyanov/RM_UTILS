# Инструкция по разработке и внесению изменений в библиотеку

## Общие принципы
Библиотека использует упрощенную модель разработки Git Flow. Все изменения вносятся через ветки, что обеспечивает чистоту основной ветки и позволяет организовать эффективный процесс code review.

## Ветки
- **`master`** — стабильная версия для production
- **`develop`** — основная ветка для разработки
- **`feature/*`** — ветки для разработки новой функциональности

## Процесс внесения изменений
### 1. Подготовка к разработке
Убедитесь, что у вас установлены все необходимые зависимости.

#### 1.1. Установите Poetry, если еще не установлен:
```bash
# Ubuntu/Debian
sudo apt install poetry

# MacOS (Homebrew)
brew install poetry

# Windows (PowerShell)
(Invoke-WebRequest -Uri https://install.python-poetry.org -UseBasicParsing).Content | python -
```

#### 1.2. Загрузите проект:
```bash
# Клонируйте репозиторий
git clone git@github.com:n-emelyanov/RM_UTILS.git
cd RM_UTILS

# Установите зависимости
poetry install
```

### 2. Создание новой ветки для разработки
Всегда начинайте работу с создания новой ветки от develop:
```bash
# Обновите локальную ветку develop
git checkout develop
git pull origin develop

# Создайте новую feature-ветку
git checkout -b feature/краткое-описание-изменения
```

### 3. Фиксация изменений
```bash
git add .
git commit -m "feat: Добавлен новый расчет метрики"
```

Рекомендуемые префиксы коммитов:

- `feat:` — новая функциональность
- `fix:` — исправление ошибки
- `docs:` — изменения в документации
- `style:` — форматирование без изменения логики
- `refactor:` — рефакторинг кода
- `test:` — добавление или исправление тестов
- `chore:` — обновление зависимостей или конфигураций

### 4. Подготовка к PR
#### 4.1. Обновление версии
Если изменения затрагивают функционал библиотеки, обновите версию в `pyproject.toml` согласно SemVer:

* `MAJOR` — обратно несовместимые изменения
* `MINOR` — обратно совместимые нововведения
* `PATCH` — обратно совместимые исправления

#### 4.2. Добавление Examples
При добавлении нового функционала следует добавить пример его использования в директорию `examples/`

#### 4.3. Обновление feature-ветки

Если во время вашей работы в develop внесли изменения, актуализируйте feature-ветку/ Предпочтительный вариант обновления:
1. Обновляем локальный `develop`:
```bash
git checkout develop
git pull origin develop --rebase
```
2. Обновляем feature-ветку:
```bash
git checkout feature/*
git rebase develop
```
### 5. Push ветки

После создания локальной ветки и внесения изменений необходимо отправить ее на GitHub:
```bash
git push -u origin feature/краткое-описание-изменения

# Если ветка уже была отправлена ранее, используйте
git push
```

### 6. Создание Pull Request

1) Перейдите в репозиторий на GitHub
2) Нажмите "Compare & pull request"
3) Укажите:
    * Целевую ветку: `develop`
    * Заполните шаблон PR
    * Добавьте ревьюверов

### 7. Процесс ревью
1) Дождитесь одобрения от назначенных ревьюверов
2) Устраните замечания, если они есть
3) Обновите ветку через rebase при необходимости


### 8. Слияние изменений
- Используйте опцию "Squash and merge" для feature-веток
- Удалите ветку после слияния.
